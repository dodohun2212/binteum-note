## 무엇을 하는 앱인가

**① 출제 포인트 순위.** 자료에서 개념을 뽑고, 학습목표·본문 쪽수·예제·연습문제와 교수님이 수업에서 한 말("이건 시험에 나와요", "꼭 알아 두세요")을 신호로 모아 출제 가능성 점수를 매긴다. 점수마다 근거 배지와 교수님 말 원문이 붙는다. "다음 주에 다시 봅니다"처럼 미룬 개념은 점수가 내려간다.

**② 취약점 진단.** 출제 점수 20점 이상인 개념 전부에 문제를 하나씩 낸다(50점 이상은 서술형, 나머지는 객관식). 필요한 문제에는 트리·배열·표 그림이 붙는다. 확신 없이 골라 맞힌 답은 '앎'이 아니라 '헷갈림'이다. 헷갈린 점을 적으면 ④에서 그 질문에 바로 답한다.

**③ 공부 순서와 오답노트.** 출제 점수 × 모르는 정도로 지금 당장 · 다음 · 복습만을 나눈다. 카드 한 장에 내 문제와 답, 채점, 정답, 강의자료 쪽 번호를 인용한 보완 설명, 원본 페이지 그림이 있다. 보완 설명은 '지금 당장' 전부, 우선순위 상위 3개, 진단에서 모름·헷갈림이 나온 개념 전부, 헷갈린 점을 적은 개념에 자동으로 만들고, 나머지는 카드의 '설명 보기' 버튼으로 만든다. 자료에 없는 내용은 "올린 자료에서 찾지 못함"으로 표시한다.

**④ 시험 대비 요약 노트.** 강의 순서대로 모든 개념을 정리한다. 중요한 개념(지금 당장, 출제 점수 50점 이상, 진단에서 모름)은 자세히, 나머지는 보통이나 한 줄로 쓴다. 교수님 말은 AI가 지어내지 않게 코드가 녹음에서 찾은 문장을 그대로 붙인다.

결과는 HTML 파일 두 개(공부 순서·오답노트, 요약 노트)로 내려받는다. 샘플로 만든 실제 결과는 [docs/결과_예시/README.md](docs/결과_예시/README.md)에 있다. 샘플을 두 번째로 해 보면 서버에 저장된 문제와 설명을 다시 써서 수 초 만에 끝난다(서술형 채점만 다시 한다).

## 사용 방법

1. 앱 주소를 연다. 잠들어 있으면 "Yes, get this app back up!"을 누르고 30초쯤 기다린다.
2. **샘플로 체험**: `🧪 샘플로 1분 체험`을 누른다. 문제를 다 풀 시간이 없으면 ③에서 `예시 답 채우기`를 누르면 된다.
3. **내 자료로 하기**: 강의자료(PDF·PPTX, 30MB까지, 한 번에 한 장)를 올리고 `분석 시작`을 누른다. 녹음(m4a·mp3·wav, 25MB까지)을 올리거나 받아쓴 대본을 붙여넣으면 교수님 말이 점수에 들어간다. 없어도 된다.
4. **빠른 진단**: 진단할 개념이 많으면 ②에서 "출제 가능성 상위 5개만 풀기"를 켠다. 직접 올린 자료는 대상이 8개보다 많으면 기본으로 켜져 있다.
5. **사용 제한**(운영자 키 하나를 모두가 쓰기 때문): 화면 하나에서 분석 5번, 서버 전체 하루 분석 150번, 하루 AI 호출 3000번.

## 어떻게 동작하나

```text
자료 → 텍스트 추출·개인정보 가리기(코드) → 개념 추출(AI 1) → 강조 발화 찾기(AI 2)
     → 출제 점수(코드) → 진단 문제(AI 3-A 서술형 · 3-C 객관식) → 채점(객관식은 코드, 서술형은 AI 3-B)
     → 우선순위(코드) → 보완 설명(AI 4) · 요약 노트(AI 5) → HTML 2개(코드)
```

AI 호출은 5종이고 모두 `core/llm.py`의 `ask_json()` 하나를 거친다. AI 답은 JSON으로 읽어 형식과 쪽 번호 범위를 검사한다. 문제·해설·채점 이유·보완 설명·요약 노트의 `(p.n)` 인용은 그 개념의 근거 페이지 안인지 코드가 확인하고, 밖이면 지운다. 교수님 말 인용은 대본에 실제로 있는 문장만 남긴다. 호출 3~5에는 그 개념이 나오는 페이지 글만 넣는다(최대 8쪽).

출제 가능성 점수 가중치(v0, `core/score.py` 맨 위 표):

| 신호 | 점수 |
|---|---|
| 학습목표에 있음 | +3.0 |
| 본문 쪽수(표지·목차·학습목표·연습문제·요약 제외) | 쪽당 +1.0, 최대 4쪽 |
| 예제·그림으로 과정 설명 | +1.5 |
| 연습문제에 포함 | +2.0 |
| 강조 발화 | +1.0 × (강도/3), 발화마다 |
| 시험 암시 | +1.5 × (강도/3), 발화마다 |
| 실수 경고 | +0.7 × (강도/3), 발화마다 |
| 연습문제 지목 | +1.0 × (강도/3), 발화마다 |
| 다음에 다룸 | −2.5, 발화마다 |
| 가볍게 넘어감 | −1.0, 발화마다 |

가장 높은 개념을 100점으로 맞춘 비교용 점수이고 확률이 아니다. 우선순위 = 출제 점수 × (1 − 이해도), 이해도는 앎 1.0 · 헷갈림 0.5 · 모름 0.0이고, 문제를 내지 않은 개념(화면에는 '아직 확인 안 함')은 중간값 0.5로 둔다. 50 이상 "지금 당장", 20~49 "다음", 20 미만 "복습만".

모델은 `claude-sonnet-5-5`이고 `config.py`의 `LLM_MODEL` 한 줄만 바꾸면 교체된다. 녹음 받아쓰기는 OpenAI 전사 API(`STT_MODEL`)를 쓴다.

## 로컬 실행

```bash
python -m pip install -r requirements.txt
```

`.streamlit/secrets.toml`을 만들어 키 이름 두 개를 적는다(값은 본인 키. 이 파일은 git에 올라가지 않는다).

```toml
ANTHROPIC_API_KEY = "..."
OPENAI_API_KEY = "..."   # 녹음 받아쓰기를 쓸 때만
```

```bash
python -m streamlit run app.py
```

키 없이 화면만 보려면 환경변수 `BINTM_FAKE_AI=1`을 켠다(정해진 모양의 가짜 답이 나온다).

## 한계와 향후 계획

- 점수는 규칙 기반 추정이다. 가중치(v0)를 실제 시험지로 검증하지 않았다. 대회 전에 원래 앱으로 실제 강의자료 7개 장을 돌려, 교수님이 시험 전에 예고한 개념 17개 중 15개가 자료만으로 진단 대상에 들었다([docs/검증_결과.md](docs/검증_결과.md)). 실제 시험지와 비교한 것은 아니다. 기출 비교 스크립트(`scripts/compare_exam.py`)는 있지만 돌리지 않았다.
- 스캔 PDF(글자가 그림인 PDF)는 읽지 못한다. 글자 인식은 향후 계획이다.
- 한 번에 한 장(chapter)을 전제로 한다. 120쪽을 넘으면 앞 120쪽만 분석한다.
- 녹음은 25MB까지다. 길면 대본 붙여넣기를 쓴다.
- 새로고침하면 결과가 사라진다. 내려받은 HTML로 보관한다. 진행 상황 저장·불러오기는 만들지 않았다.
- 분석 횟수는 서버 메모리에서 세므로 서버가 다시 켜지면 0부터 센다.
- AI가 만든 문제와 설명에는 틀린 내용이 있을 수 있다. 쪽 번호 인용으로 원문을 확인할 수 있게 했다.
- 스크린샷은 넣지 못했다. 화면 대신 결과 예시를 읽을 수 있다.
- 향후: 기출 비교로 가중치 조정, 모델 교체 비교, 학우 질문 기록, 여러 장 묶어 보기.

## 데이터 처리·저작권·녹음 동의

- 올린 자료와 녹음은 분석을 위해 AI 제공사(Anthropic, OpenAI) 서버로 전송된다.
- 올린 파일은 서버 디스크에 저장하지 않는다. 결과는 세션이 끝나면 사라지고, 같은 파일의 분석 결과와 쪽 그림은 서버 메모리에 두었다가 서버가 다시 켜지면 사라진다. 녹음 받아쓰기에 쓰는 임시 파일은 보낸 직후 지운다.
- 학번·주민등록번호·전화번호·이메일은 자료와 대본 모두 AI에 보내기 전에 가린다.
- 녹음은 교수님 허락을 받은 것만, 개인 학습 목적으로만 올린다. 녹음을 공유하거나 저장하는 기능은 없다.
- 저장소에는 직접 만든 가상 샘플 자료만 있다. 교재 PDF, 실제 녹음, 기출 문제는 없다.
- API 키는 코드와 저장소에 없다. `st.secrets` → 환경변수 순으로만 읽는다.
